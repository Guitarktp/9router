# Upgrade Custom Pegasus to 9Router v0.5.81 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge upstream 9Router v0.5.81 into `custom/pegasus` without regressing per-API-key provider/connection routing, Claude weekend routing, or the localhost:20128 deployment.

**Architecture:** Merge the release tag inside an ignored linked worktree branched from `custom/pegasus`. Compose upstream changes with existing custom routing, verify focused regressions and a standalone production build, then fast-forward the main checkout and restart its launchd-managed server.

**Tech Stack:** Next.js 16, React, Node.js, Vitest, SQLite, git worktrees, macOS launchd/nginx.

**Spec:** User request in this task; existing custom behavior is defined by the `api-key-*`, `claude-weekend-*`, provider-view, database-migration, dashboard-guard, and model-lookup unit tests.

## Global Constraints

- Preserve the user-owned unstaged `CLAUDE.md` change in the main checkout.
- Keep `/Users/user/.9router` as the live data directory and `http://localhost:20128` as the nginx entry point.
- Preserve API-key-specific provider and connection selection plus Claude weekend routing.
- Do not push to GitHub unless explicitly requested.
- Do not run `npm audit fix --force`.
