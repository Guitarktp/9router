# Upgrade Custom Pegasus to 9Router v0.5.75 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge upstream 9Router v0.5.75 into `custom/pegasus` without regressing per-API-key provider/connection routing, Claude weekend routing, or the localhost:20128 deployment.

**Architecture:** Perform the merge in an ignored linked worktree branched from `custom/pegasus`. Resolve overlapping files by composing upstream behavior with the existing custom routing context, verify focused custom regressions and a production build, then fast-forward the main checkout and restart its launchd-managed standalone server.

**Tech Stack:** Next.js 16, React, Node.js, Vitest, SQLite, git worktrees, macOS launchd/nginx.

**Spec:** User request in this task; existing behavior is defined by the tests matching `tests/unit/api-key-*`, `tests/unit/claude-weekend-*`, `tests/unit/header-provider-view-context.test.js`, and related routing tests.

## Global Constraints

- Preserve the user-owned unstaged `CLAUDE.md` change in the main checkout.
- Keep the live database at `/Users/user/.9router` and nginx entry point at `http://localhost:20128`.
- Do not replace custom provider or connection selections with global-only routing.
- Do not push to GitHub unless the user explicitly asks.
- Do not run `npm audit fix --force` as part of this upgrade.
