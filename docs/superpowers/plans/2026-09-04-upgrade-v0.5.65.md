# 9Router v0.5.65 Custom Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `custom/pegasus` from upstream v0.5.55 to v0.5.65 without regressing per-API-key provider/connection routing or Claude weekend routing.

**Architecture:** Merge the signed upstream tag into an isolated integration branch, compose both sides of the three textual conflicts, then adapt upstream's new catch-all model lookup route to reuse the existing API-key routing context. Validate the combined request path from model discovery through chat credential selection before merging back to the live branch.

**Tech Stack:** Next.js 16, React 19, JavaScript, Vitest, ESLint, Git worktrees

**Spec:** `docs/superpowers/specs/2026-08-24-api-key-provider-routing-design.md`, `docs/superpowers/specs/2026-08-25-api-key-connection-routing-design.md`, and `docs/superpowers/specs/2026-08-31-claude-weekend-quota-routing-design.md`

## Global Constraints

- Preserve the uncommitted `CLAUDE.md` in the primary checkout.
- Keep global routing behavior unchanged when an API key has no explicit provider or connection policy.
- Apply Claude weekend filtering after the per-key connection policy and before account availability/rate-limit selection.
- Preserve upstream v0.5.65 Antigravity quota handling, Claude `[1m]` model normalization, 503 rate-limit response, provider status filter, and Grok CLI bulk import.
- Do not rebuild or restart the live 20128/20129 service until all isolated verification passes.
